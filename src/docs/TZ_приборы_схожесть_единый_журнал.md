## 1. Цель

1. Ввести сущность **«Прибор»** (модель и серийный номер) и связать каждую запись ЭКГ с прибором, чтобы в журнале было видно, что записи *сняты в одно время, но разными приборами*.
2. Добавить каждой записи ЭКГ поле **«биологическая схожесть с эталонным шаблоном» (в %)**, вычисляемое автоматически при импорте. Записи с низкой схожестью подсвечивать в журнале.
3. Устранить **дублирование кода журнала ЭКГ** (две реализации: `ECGListDialog` из недельного heatmap и `ECGListWindow` из главной формы), оставив **одну** версию с сортировкой по нескольким полям — как по времени снятия (`recorded_at`), так и по времени импорта (`updated_at`).

## 2. Текущее состояние (исходные данные для рефакторинга)

### 2.1 Модель данных — `models.py`
- `Athlete` — строка, `id` (String), ФИО, параметры, `polar_id` (String, unique).
- `ECGRecord` — `athlete_id` FK, `recorded_at` (String), `duration_seconds`, `updated_at` (DateTime), `mean_hr`, `rmssd`, `sdnn`, `status`, `stress_si`, `tp`. **Никаких полей прибора и схожести нет.**
- `ECGRaw` — `record_id` PK, `raw_data` (Text). В сырых данных хранится `polar_id`.
- `BiometricTemplate` — шаблон на атлета (`shape_template`, `spectrum_template` как JSON), `records_used`, `created_at`.

Подключение: `models.get_session(db_path)` через SQLAlchemy + SQLite; `Base.metadata.create_all` создаёт **только новые** таблицы и **не добавляет** колонки к существующим.

### 2.3 Импорт — `importer.py`
- `_parse_header(raw)` читает из шапки файла `datetime=` и `polar_id=`.
- Атлет подбирается по `polar_id` (`athlete[5] == polar`).
- Биометрическая проверка: `check_ownership_with_saved_template(db_path, aid, path)` возвращает `(status, distance, prob)`; `prob` — вероятность совпадения 0..1, показывается как `prob*100` в диалоге `BiometricChoiceDialog`. **В запись не сохраняется.**
- Запись сохраняется через ORM без `device_id` и `bio_similarity_pct`.

### 2.4 Биометрия — `ecg_biometrics.py`
- `cfg` (класс `ECGConfig`): пороги, веса, `BIOMETRIC_THRESHOLD`, `MATCH_WARNING_THRESHOLD`, бонусы надёжности.
- Возвращаемая вероятность `prob` — и есть источник процента схожести.

### 2.5 Ключевой факт сырых данных
Устройство (polar_id) **не равно** атлету: записи одного поля встречаются у нескольких людей, у одного человека — записи нескольких приборов. Поэтому прибор — отдельная сущность, а не колонка у атлета.

## 3. Требования

### 3.1 Таблица «Приборы» (`Device`)
| Поле | Тип | Примечания |
|---|---|---|
| `id` | Integer PK | автоинкремент |
| `model` | String | модель прибора; **по умолчанию "Polar H10"** (в файле нет), редактируется |
| `serial_number` | String, UNIQUE | = `polar_id` из шапки файла (например `C8219D21`) |
| `created_at` | DateTime | авто |

- `ECGRecord.device_id` — FK → `Device.id`, **nullable** (для старых записей допускается NULL).
- При импорте: парсим `polar_id` → `SELECT/INSERT` в `Device` по `serial_number` → записываем `device_id` в запись.
- Связь «прибор обычно у такого-то атлета» — **не жёсткая колонка**, а статистический вывод (по большинству записей), чтобы не противоречить реальным данным.

### 3.2 Поле «Биологическая схожесть» (`bio_similarity_pct`)
- `ECGRecord.bio_similarity_pct` — Float 0..100, **nullable**.
- Вычисляется **автоматически при импорте** из `prob` биометрической проверки: `bio_similarity_pct = prob * 100`.
- Для пакетного (неинтерактивного) импорта, где биометрия сейчас не считается — считается, но без диалогов (только сохраняется).
- Отображается в журнале колонкой «Сходство, %».

### 3.3 Единый журнал ЭКГ с сортировкой
- Оставить **одну** реализацию `ECGJournal(CTkToplevel)` — на базе нынешнего `ECGListDialog` (customtkinter, есть экспорт/удаление).
- `ECGListWindow` удаляется; точка вызова в `atlets.py` переключается на `ECGJournal`.
- Два режима входа (сохранение текущего UX):
  - от heatmap: атлет + интервал `[recorded_at]`, сортировка по умолчанию — **время снятия**;
  - от главной формы: атлет (или «все») + лимит N, сортировка по умолчанию — **время импорта** (`updated_at` DESC).
- Сортировка **кликом по заголовку** любой колонки (через `order_by`), а также явный переключатель «По времени снятия / По времени импорта».
- Колонки журнала (единый набор):
  - Атлет (ФИО)
  - Прибор (модель + серийный номер)
  - Дата измерения (`recorded_at`)
  - Дата импорта/обновления (`updated_at`)
  - Сходство, %
  - ЧСС, RMSSD, SDNN, ИС, TP, Статус

### 3.4 Подсветка низкой схожести
- Однопороговое выделение по двум уровням:
  - `bio_similarity_pct < 50` → жёлтый (`COL_WARN`);
  - `bio_similarity_pct < 30` → красный (`COL_CRIT`).
- Пороги вынести в `app_constants.py`:
  - `BIO_SIMILARITY_WARN_PCT = 50`
  - `BIO_SIMILARITY_CRIT_PCT = 30`

## 4. Миграция БД

`Base.metadata.create_all` новые таблицы (`device`) создаст, но колонки `ecg_records.device_id` и `ecg_records.bio_similarity_pct` к существующей таблице **не добавит**. Нужен шаг миграции при старте / утилитой:

1. `ALTER TABLE ecg_records ADD COLUMN device_id INTEGER REFERENCES device(id)`
2. `ALTER TABLE ecg_records ADD COLUMN bio_similarity_pct FLOAT`
3. Создать таблицу `device` (`CREATE TABLE IF NOT EXISTS`).
4. **Бэкфилл** `device_id` для старых записей: для каждой записи без `device_id` — прочитать `polar_id` из `ecg_raw.raw_data`, найти/создать `Device`, проставить связь.
5. Контроль идемпотентности: повторные запуски не должны дублировать данные или падать (проверка существования колонок через `PRAGMA table_info`).

Образцы существующих миграционных скриптов: `scripts/migrate_split_raw.py`, `scripts/prepare_database.py`.

## 7. Риски и примечания

1. **Дубликат по `recorded_at`**: сейчас проверка в `importer.py` идёт по `recorded_at`; переход на прибор не отменяет её — сохраняем как есть.
2. **Старые записи без схожести**: `bio_similarity_pct` останется NULL (колонка «—»), при желании добавим «пересчитать для выбранной записи» (вне объёма этой версии).
3. **Бэкфилл разбора raw** может быть медленным для больших БД — выполнять один раз, по возможности в фоне/через утилиту.
4. **Модель прибора** в файле отсутствует — только серийник; `model` заполняется "Polar H10" по умолчанию и подлежит ручной корректировке.
